# RMF Buddy

Interactive web app for studying NIST RMF, NIST 800-53 controls, DoD CCIs, eMASS workflow,
GRC frameworks (ISO 27001, SOC 2, PCI-DSS, HIPAA, GDPR, SOX, FedRAMP, CMMC, etc.), and
MITRE ATT&CK mappings. Built around an agentic chat that calls live tools against an
authoritative local database.

## Tabs

- **Chat** — Q&A across the entire knowledge base. Templates for compare-controls,
  implementation statement, assessment plan, POA&M draft, test result.
- **Controls** — search 1,196 NIST 800-53 Rev. 5 controls (also by CCI ID); filter by
  family + baseline; per-control view with CCIs and ATT&CK technique coverage; baseline diff.
- **eMASS Guide** — 33 curated topics + 91-term glossary for the DoD eMASS workflow.
- **GRC Guide** — 21 topics + 87-term glossary across compliance frameworks and risk theory.
- **NIST Docs** — 41-publication searchable library (800-37, 800-53, 800-53A, 800-53B,
  800-60, 800-30, 800-37, 800-39, 800-61, 800-63, 800-82, 800-128, 800-137, 800-160,
  800-171/172, 800-207 Zero Trust, 800-218 SSDF, FIPS 199/200/140-3/197/180-4/186-5,
  CNSSI 1253, NIST CSF 2.0, etc.).
- **Practice** — flashcards drawn from the catalog and AI-generated scenarios with
  scoring + feedback.

## Architecture

- **Backend**: Python 3.9+ FastAPI. SQLite (`backend/rmf.db`) for the catalog. Local
  semantic search via `sentence-transformers/all-MiniLM-L6-v2` (no external embedding
  API). Agentic loop using OpenAI-compatible chat completions through OpenRouter.
- **Frontend**: React + TypeScript + Tailwind, Vite 7.
- **Live web tools**: Firecrawl with a strict allow-list (`*.nist.gov`, `*.cyber.mil`,
  `*.mitre.org`, `*.disa.mil`, `cnss.gov`).
- **Data sources** ingested at build time:
  - NIST 800-53 Rev. 5 catalog (OSCAL JSON)
  - NIST 800-53B baselines (Low/Moderate/High, OSCAL JSON)
  - DoD CCI List (XML)
  - MITRE Center for Threat-Informed Defense ATT&CK ↔ 800-53 mapping (5,314 mappings)

## Setup

### 1. Backend

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m app.ingest        # parses sources into rmf.db (~30s on first run)
cp .env.example .env        # then edit .env with your keys (see below)
uvicorn app.main:app --host 127.0.0.1 --port 8911 \
  --no-server-header --no-date-header
```

Required environment in `backend/.env`:

```
OPENROUTER_API_KEY=...        # required for chat + scenario generation/grading
OPENROUTER_MODEL=openai/gpt-4o   # any OpenRouter model with tool-calling support
FIRECRAWL_API_KEY=...         # required only for live web_fetch / web_search tools
```

The ingestion step downloads source files into `data/` if missing
(`catalog.json`, `low.json`, `mod.json`, `high.json`, `U_CCI_List.xml`,
`attack_map.json`).

### 2. Frontend

```bash
cd frontend
npm install
npm run dev   # http://localhost:5173 (proxies /api to 127.0.0.1:8911)
```

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| GET  | `/api/health` | Liveness |
| GET  | `/api/families` | The 20 control families with counts |
| GET  | `/api/controls` | Filter controls (family / baseline / q / CCI) |
| GET  | `/api/controls/{id}` | Full control + CCIs + baselines + ATT&CK |
| GET  | `/api/controls/{id}/attack` | Just ATT&CK techniques mitigated |
| GET  | `/api/ccis/{cci_id}` | A single CCI |
| GET  | `/api/baselines/diff` | Diff between Low/Moderate/High |
| GET  | `/api/emass/topics` | eMASS knowledge base index |
| GET  | `/api/emass/topics/{slug}` | Single topic body |
| GET  | `/api/emass/glossary` | eMASS glossary |
| GET  | `/api/grc/topics` | GRC knowledge base index |
| GET  | `/api/grc/topics/{slug}` | Single GRC topic body |
| GET  | `/api/grc/glossary` | GRC glossary |
| GET  | `/api/nist/publications` | NIST publication library |
| GET  | `/api/nist/publications/{slug}` | Single publication |
| GET  | `/api/study/flashcards` | Random flashcards |
| GET  | `/api/study/scenario` | Generate a practice scenario |
| POST | `/api/study/grade` | Grade a scenario answer |
| POST | `/api/chat/stream` | Agentic streaming chat (SSE) |

## Security

See `SECURITY_FIXES.md` for the threat model and the full audit report. The server is
designed for **single-user local use** only — it binds 127.0.0.1, has no end-user auth,
and CORS is restricted to localhost. If deploying publicly, add authentication, HSTS,
and rate limiting first.
